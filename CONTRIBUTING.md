# Contributing to Boron Notes

Thank you for your interest in contributing! We welcome all contributions, from bug reports and documentation fixes to major new features. 

Please take a moment to review this document before you get started.

---


## 🐛 How to Report a Bug

If you find a bug, please check the [Issues page](link-to-issues) first to see if it has already been reported. If it hasn't, please open a new issue and include:

*   **A clear summary** of the problem in the title.
*   **Step-by-step instructions** to reproduce the issue.
*   **Expected vs. actual behavior**.
*   **Environment details** (e.g., OS, browser version, runtime version).
*   **Screenshots or code snippets** if applicable.

## 💻 Local Development Setup

To set up the project locally, follow these steps:

1.  **Fork the repository** on GitHub.
2.  **Clone your fork** to your local machine:
    ```bash
    git clone https://github.com[your-username]/[repository-name].git
    cd [repository-name]
    ```
3.  **Install dependencies**:
    ```bash
    [e.g., npm install / pip install -r requirements.txt / bundle install]
    ```
4.  **Create a new branch** for your work:
    ```bash
    git checkout -b feature/your-feature-name
    ```

## 🧪 Testing & Linting

Before submitting your code, please ensure it meets our quality standards:

*   **Run Code Linters**: Ensure your code follows our style guide by running `[e.g., npm run lint / flake8]`.
*   **Run Unit Tests**: All tests must pass before a merge. Run tests using `[e.g., npm test / pytest]`.
*   **Write New Tests**: If you are adding a feature or fixing a bug, please write tests that cover your changes.

## 🚀 Pull Request Checklist

When you are ready to submit your changes, open a Pull Request (PR) against our `main` (or `trials`) branch. Make sure your PR includes:

*   [ ] A descriptive title referencing any related issue (e.g., `Fixes #123`).
*   [ ] A clear description of the changes you made.
*   [ ] Green lights on all automated tests and linters.
*   [ ] Updated documentation if your changes alter how the application works.

Once submitted, a maintainer will review your PR. We may ask for changes or clarifications before merging.

## ❓ Need Help?

If you have questions or get stuck, feel free to open a discussion by dropping a comment in your open issue/PR.

Thank you for making Boron Notes better!
